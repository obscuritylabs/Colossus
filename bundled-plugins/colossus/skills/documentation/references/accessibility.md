# Inclusive and accessible documentation

Use precise, respectful language. Avoid assumptions about the reader's identity,
abilities, location, culture, or experience. Use gender-neutral language where gender
is irrelevant, and respect a community's self-identification. Preserve exact product
and API names while using inclusive terms in surrounding prose.

Write meaningful link text and semantic headings in a logical hierarchy. Do not use
color, position, or visual appearance as the only way to communicate an instruction.
Refer to UI elements by their labels, and use device-neutral actions when appropriate.

Give informative images useful alternative text describing their purpose in context.
Treat decorative images according to the renderer's accessibility conventions.
Explain essential information from diagrams in adjacent text. Avoid images of text
when ordinary text can serve the same purpose.

Use simple tables with clear headers. Keep essential explanations available as text
rather than relying only on a screenshot or visual cue. Do not claim compliance with
an accessibility standard solely because this guidance was followed.
