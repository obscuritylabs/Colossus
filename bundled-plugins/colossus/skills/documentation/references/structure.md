# Page structure and navigation

Start with the reader's goal and the information needed to act. Organize the page
around tasks or concepts rather than the implementation's file layout. Use the
repository's required page type, frontmatter, and navigation conventions.

Use descriptive headings in sentence case. Keep heading levels in order and use
parallel wording for sibling sections. Task headings should name the task; concept
headings should name the concept. Avoid vague headings and headings that repeat
without helping readers navigate.

Use numbered lists when order matters and bullets when it does not. Keep items
parallel. Use a table when readers need to compare values across consistent columns,
not to simulate a page layout. Introduce a list or table with enough context to
understand its purpose.

Use descriptive link text that makes sense outside its sentence. Prefer a specific
page or section over a site's home page. Avoid bare "click here" links and directional
references that depend on page layout. Check links and anchors after changing headings.
