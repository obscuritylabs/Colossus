# Procedures and notices

State the outcome and prerequisites before the steps. Put a condition before the
instruction it controls. Keep steps focused on reader actions, generally using an
imperative verb. Use numbered steps for a sequence and keep independent actions
separate. Explain the expected result where it helps readers verify progress.

Use exact UI labels and the repository's formatting conventions. Separate reader
input from system output. Distinguish required actions from optional paths, and give
readers the information they need before a consequential decision.

Keep the main path concise. Put background and alternatives where they do not
interrupt the sequence. Include cleanup, verification, and recovery when the task
needs them; do not impose empty sections on a small procedure.

Use notices sparingly and follow the site's existing notice syntax. Put information
needed to complete a task in the main flow rather than hiding it in a note. Place a
warning before the action that can cause harm or loss; explain the consequence and
how to avoid it. Do not use notices merely to repeat the preceding text.
