# Code, APIs, and commands

Use code formatting for identifiers, filenames, literal values, and commands. Preserve
case, punctuation, and exact public names. Follow the repository's conventions for
signatures, parameter descriptions, types, return values, and errors.

Introduce each sample with what it demonstrates and what readers need to run it.
Keep examples focused, valid for the documented version, and consistent with the
project's language style. Use fenced blocks with a language identifier supported by
the documentation renderer. Separate commands, output, and explanatory prose.

Make replaceable values obvious and explain them. Do not include shell prompts that
readers might accidentally copy. For multiline commands, use continuation syntax for
the named shell. Distinguish a complete runnable example from a fragment, and explain
omitted setup. Use safe example data instead of real credentials or private records.

Explain the sample's result and relevant failure behavior. Check documented commands
and examples using the repository's established validation; reading this reference
alone does not authorize executing a sample or accessing its network destinations.
Do not copy upstream code samples into this reference without preserving their
separate Apache 2.0 licensing requirements.
