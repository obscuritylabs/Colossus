# Offline and Airgapped Operation

Colossus is designed to remain useful without internet access. The default provider is
`echo`, bundled skills ship with the package, and offline bundles can be verified from
local manifests and checksums.

## Baseline offline mode

From a prepared checkout or installed wheel:

```bash
uv run colossus --provider echo run "hello"
uv run colossus skills list
uv run colossus tools list
```

This validates the CLI, skill discovery, built-in tool metadata, state path, and audit
path without contacting a model API.

Offline-safe built-ins include filesystem read/write tools, git inspection, structured
shell execution, task and plan tracking, patch tools, repo context tools, verification
wrappers, trace export, and local eval wrappers. `web.fetch` and `docs.fetch` are
network-capable, approval-gated tools and should not be approved in airgapped profiles.
`web.search` and networked MCP execution remain adapter extension points.

Context compaction works offline. If model-assisted summarization is unavailable or
fails, Colossus uses deterministic snapshots and keeps raw session history intact.

## Local model endpoint

Use `local_openai_chat` for an OpenAI-compatible local service:

```json
{
  "provider": {
    "kind": "local_openai_chat",
    "model": "local-model",
    "base_url": "http://localhost:8000/v1",
    "api_key_env": null,
    "ca_bundle": null
  },
  "allow_user_skill_overrides": false
}
```

The local provider sends requests to an OpenAI-compatible chat endpoint. Use a custom
CA bundle when the endpoint is HTTPS with private trust roots.

## Preparing dependencies before isolation

Before entering an airgapped environment, prepare and review:

- The source distribution and wheel generated by `uv run python -m build`.
- A wheelhouse for runtime and development dependencies if tests will run offline.
- The exact `uv.lock` used to build and test.
- Any local model server image, model weights, and endpoint configuration.
- Offline bundles with manifests, checksums, SBOM, signatures, and included skills.

Keep the prepared artifacts immutable once signed or checksummed.

## Airgap verification checklist

Inside the isolated environment:

```bash
uv run colossus bundle verify ./bundle
uv run colossus config show
uv run colossus skills list
uv run colossus tools list
uv run colossus context show --session smoke-session
uv run pytest
uv run ruff check .
uv run mypy src/colossus
```

For production use, retain the verification output, bundle manifest, release checksums,
and audit logs with the release record.

## Operational controls

- Keep `allow_user_skill_overrides` disabled unless overrides are reviewed and pinned.
- Run local model endpoints on private interfaces when possible.
- Route subprocess execution through the brokered tool layer only.
- Preserve append-only audit JSONL files for incident response and release review.
- Prefer read-only mounted wheelhouses and bundles after installation.
